# AI Agent Instructions for t_demos

This file provides critical instructions for AI coding assistants working on the `t_demos` repository.

## Repository Policies

1.  **No Generated Artifacts**: Never commit `flake.nix`, `flake.lock`, or the `_pipeline/` directory. These are generated by the T orchestration engine at runtime and should remain local.
2.  **Gitignore Integrity**: Do not modify the `.gitignore` file unless specifically instructed by the USER.
3.  **T-Project Configuration**: In `tproject.toml` files, **never include a `nixpkgs` date**. Let the engine handle the default pinning to ensure compatibility across demos.
4.  **Adding New Demos**:
    *   When creating a new demonstration project, always add a corresponding GitHub Action in `.github/workflows/`.
    *   **Process**: Copy an existing workflow file (e.g., `test_r_interop_t.yml`) and modify only the necessary fields (name, path, and script to execute).
    *   Ensure the workflow uses the same Nix-based testing pattern as the other demos.

## Pulling & Pushing

*   Always pull from `master` before starting work.
*   Commit and push directly to `master` unless the USER requests a feature branch.
